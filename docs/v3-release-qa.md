| Review finding | Root fix in 0.2.3 |
|---|---|
| **1 — reconnect can run two pipelines; either stop hides the other lane** | One singleton `CaptureCoordinator` owns `CaptureOwnership`. A serialized owner permit gates every pipeline publish/close and shared running/readiness change. **Silent wins**: it closes the projection pipeline before taking ownership. Projection keeps the driver's one-shot platform grant and virtual display, drains/discards images without bitmap conversion or OCR while parked, and receives a fresh permit if silent stops or fails. Stopping the Android projection would destroy that grant, so its casting indicator can remain while parked. A parked projection stopping cannot clear silent readiness, and silent stand-down cannot clear a resumed projection. |
| **2 — an old NoCapability/DISABLE branch consumes a replacement's state** | Every silent loop has an immutable session token. Start, stop, stand-down, cleanup and publication share the ownership monitor; stale generations do nothing. Completion cleanup also covers cancellation before a lazy coroutine body starts. Reconnect only reuses a loop that still owns capture, and reasserts readiness after binding. The accessibility supervisor no longer performs unscoped silent-lane cleanup. |
| **3 — inline success followed by synchronous cancellation bypasses arbitration** | Extracted `ScreenshotCompletion` gives success, callback cancellation and synchronous cancellation one atomic gate. Cancellation uses `cont.cancel()` only if it wins. Losing frames and promptly cancelled undelivered frames are recycled exactly once. Unexpected cancellation releases the current silent session; a live fallback remains ready. Projection consumer completion also removes a dead fallback when cancellation leaves its supervisor active. This is adapter robustness, not a claim that Samsung normally throws cancellation. |
| **4 — initial parser rejection, empty OCR and own UI are silent** | Throttled `EMPTY_OCR`, `NO_OFFER_SIGNATURE`, `SIGNATURE_UNPARSED` and `OWN_UI` reasons contain only counts/booleans. Each host-window burst reports frames, OCR blocks, signatures, parses, published offers, observed chip-visible frames and all hidden-reason counts, including suppressed messages and zero-frame failures. Publication and observed visibility are separate counters; publishing an offer does not prove overlay attachment. Both lanes start/end bursts, including direct host changes. Live foreground polling refreshes static hosts and clears departed hosts. Projection burst generations reject delayed frames after leaving/re-entering the same host. |
| **5 — repeated screenshot rate limiting explains nothing** | `SCREENSHOT_RATE_LIMIT` logs the consecutive-response count at most once per five seconds. Every refusal contributes to the burst summary. Success, other responses and new host windows reset the consecutive count; bounded hard-error handling remains intact. |
| **R1 — API 26–29 reconnect clears readiness while projection continues** | Every accessibility bind republishes the actual coordinator owner before any silent-lane API/capability check. Retained projection restores `captureRunning=true` and the shared running flags without waiting for a frame or reusing old read proof. Lector and explicit consent use actual ownership rather than API level or an assumed silent failure; permission/pause checks and onboarding navigation remain intact. |
| **R2 — a projection with no virtual display becomes a dead fallback** | Extracted, Android-free `ProjectionStartup` requires a non-null display and a wired ImageReader before registering availability. Failed setup releases the reader, display/projection and foreground notification, and cannot enter retained fallback ownership. JVM tests exercise null results, thrown setup stages, cleanup and registration ordering. |
| **R3 — setup failure before registration loses the stopped incident** | Serialized `CaptureOwnership.startupFailed()` publishes a stopped incident only if no owner survives. The same real readiness repository used by the app verifies stopped-tab/watchdog eligibility without an owner and unchanged state with a live silent or projection owner. A concurrent registration test verifies the outage decision shares the ownership monitor. |
